# XIRASM 0.2.21

本版本让 Meta 语言可以枚举目录，并把 Android 资源表的构造从"逐条声明"推进到
"扫描整棵资源目录树"。

- `fs.list_dir(path)` 以字符串列表返回目录内直接子条目的名字，按字节序升序排列，
  因此列举结果不依赖文件系统碰巧返回的顺序。`fs.is_dir(path)` 判断路径是否为
  目录，路径无法解析时回答 false，而 `fs.list_dir` 报错。
- 两者都走与其它文件 API 相同的受控解析器：目录支持由宿主提供，不能枚举目录的
  宿主报告路径不可用而不是猜测。与其它文件助手一样，它们在 `late_layout` 与
  `defer` 中不可用。
- `include/format/apk.inc` 新增资源树扫描。`apk_res_dir(app, "res")` 读整棵树并
  声明读到的东西：文件目录 `<类型>[-<限定符>...]` 贡献一条文件资源，资源名取
  文件名第一个点之前的部分（归档条目保留原文件名）；`values*` 目录按 TOML 表的
  每个键贡献一条字符串资源；约定名 `app_name` 与 `mipmap/ic_launcher` 会在应用
  没有显式设置应用名与图标时自动绑定。
- 扫描递归进行，跳过点开头的条目，顺序取排序后的目录枚举，所以同一棵树每次产出
  相同字节，扫两遍也无害。
- 限定符规则严格，因为资源表只编译密度与语言两个轴。限定符可以是密度名、两字母
  语言码，或 `-v4` 这类被接受但不写进配置的 API 版本限定符。一个目录最多带一个
  密度和一个语言，别的写法报错而不是被静默丢弃；同一个资源配置被两个文件同时
  声明同样报错。
- 字符串资源现在也支持两字母语言配置，`values-zh` 目录就是这种配置。
- Android 指南记录了扫描规则、验收脚本和签名边界：签名留在汇编器之外，文档给出
  了用 SDK 工具的一条完整命令序列，以及自签名调试证书需要注意的地方。
- `tests/format/android_gl_demo/` 把整条链路放在一处：GLES2 渲染器库与包住它的
  归档都由汇编器产出，纹理与启动图标都是汇编期按公式生成的。产物 39 KB 上下，
  没有 DEX、没有 C++ 运行时、没有第三方素材；验收脚本会先按源码重建一遍，再用
  `aapt2` 与 `zipalign` 复核。

- 解析不到的名字现在会把名字写进消息里：表达式里的未声明名字会连表达式一起回显，
  未知调用会报出被调用的名字，原先掩盖这两种情况的两个错误恢复各自的身份，解析
  错误的映射也从"其余都归一类"改为逐个列出。接口调用语句也可以跟行尾注释，与
  处理器指令一致。

- Meta 助手新增 `deflate.compress`：返回裸 DEFLATE 流（ZIP method 8 条目存的就是
  它），可选 1 到 9 的级别。归档层跟着支持压缩条目，APK 里因此可以让 deflated 的
  assets 与 Android 要求的未压缩资源表、共享库共存。条目记的 CRC-32 始终是未压缩
  数据的校验值，验收脚本用独立的解压器核对。

- 平台自己的资源 ID 现在有一份生成目录
  （`format/android/generated/framework_ids.inc`），由 aapt2 读平台 jar 生成。
  清单因此可以按 ID 引用 `@android:style/Theme.DeviceDefault`，`apk_use_theme_id`
  把它写进应用主题。

```asm
import("format/apk.inc")

origin(0)

let app: map = apk_new("com.example.tool", 1, "1.0", "demo")
app = apk_res_dir(app, "res")
apk_emit(app)
```

两档密度图标、一个语言变体、一个 drawable 和一个 raw 文件的资源树会同时进入归档
与资源表；`aapt2` 能从产物里逐条读回每个资源名、配置与归档路径，`zipalign
-c -P 16 4` 也接受它。`zig build test` 用一份真汇编的 fixture 覆盖目录内建，章节
13 的参考产物会列举目录树并询问目录与文件，另有两条反例钉住 `late_layout` 与
`defer` 中列举会被拒绝。

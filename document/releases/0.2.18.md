# XIRASM 0.2.18

This release adds statement macros to the Zig frontend. Macro bodies execute
when reached during source lowering; encoding, layout and relaxation do not
rerun the Meta program.

```asm
import("arm/arm64-macros.inc")
const VALUE: u64 = 42
movz x0, #VALUE
add x1, x0, #(VALUE + 1)
b.eq done
done:
ret
```

- Top-level `macro` declarations support exact arity overloads, trailing variadic
  parameters, nested calls and existing Meta variables and control flow.
- Immutable `operand` values preserve caller bindings. `operand.text`,
  `operand.eval`, `operand.slice` and `operand.split` expose spelling, expression
  evaluation and checked operand manipulation.
- Native instruction forwarding preserves captured parameters without rescanning
  inserted text. `isa(text)` explicitly bypasses macro dispatch.
- Errors retain macro invocation and definition locations, including errors
  reported during native encoding and deferred finalization.
- Deferred local declarations correctly shadow outer bindings when frozen.
- Recursion, expansion count, operand nesting and capture dependencies have
  explicit limits; allocation failures propagate with ownership cleanup.

The opt-in A64 include wraps the existing integer, branch and memory/address
families. It does not cover all A64 instructions or floating-point/SIMD APIs.
Macro names are not automatically scoped by ISA. Static labels remain module
labels; use `sym.unique` and `label.define` for private labels. Captures copy
visible value bindings, so save evaluated values when source syntax is no longer
needed. The API-only `arm/arm64.inc` remains available.

See [Statement Macros in the language guide](../language.md#statement-macros)
and the [API reference](../api-reference.md#statement-macros) for the complete
contract. `zig build test-macros` runs the frontend tests and A64 macro fixtures.

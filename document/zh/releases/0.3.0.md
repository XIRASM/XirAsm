# XIRASM 0.3.0

这是一次"审计版"发布：整个前端按"输入派生是否安全"重扫了一遍，布局事实用**独立实现的格式读取器**逐条核对，命令行则砍到只剩汇编器真正必须被告知的东西。三个会**静默产出错误结果**的缺陷被修掉，原本"位置对但没用"的诊断也改成说清该改什么。

## 输入有界，失败有位置

此前所有嵌套都没有上限，于是几 KB 的源文件就能让进程**静默死于栈溢出**：8000 层嵌套块、16000 层括号、4000 层 `list.of`、200 KB 的嵌套数组配置，全都没有任何输出。现在每条嵌套轴都有上限，并且**带位置和原因**报错。

- 语句最多嵌套 128 层（`StatementNestingTooDeep`），表达式与聚合字面量 64 层（`ExpressionNestingTooDeep`、`StructNestingTooDeep`），`toml.parse`/`json.parse` 读取的文档 64 层（`NestingTooDeep`）。**扁平的运算符链不算嵌套**，不受限。
- TOML 扫描器先前证明的是 `pos + 2 <= len`，却去读 `source[pos + 2]`：配置以两个引号结尾时（`x = """ab""`，无末尾换行）会**越界读一字节**——带检查的构建直接 panic，发行版则是越界读。两处多行串扫描现在都要求"读三字节就要有三字节"。
- `\U` 转义在 21 位类型上累加，8 位十六进制会先丢掉高位再比较，于是超范围转义**绕回合法区间**。现在累加用更宽的类型，并在收窄前先查范围。
- `virtual.begin()` 不带参数、以及为已保存的 `defer`/`late_layout` **冻结 `here()`** 的路径，读活动地址时都漏了其它布局 API 都会做的游标同步。游标只在指令**编码后**才把它算进去，所以 `mov eax, 1` 之后开的段起点是 0x4000 而不是 0x4005，冻结地址也错得一样。三处现在都先同步。

## 布局事实与自己的声明一致

共享库放置段时，只保证地址与文件偏移按页同余（可加载段必须满足的关系），却**没有**额外满足其自身节声明的对齐：`.bss` 落在 0x119D、`.data` 落在 0x219D，而两者声明的对齐是 8——这对"假设地址已对齐"的代码是不成立的承诺。现在段的文件位置从该对齐开始，**地址与文件偏移一起移动**，页同余保持不变。

所有登记在册的格式夹具现在都会用**独立实现的四格式读取器**读回，并核对四条不变量：声明的区间不越出文件、任意两段不在文件或地址空间重叠、声明的对齐被遵守、头部推导出的尺寸与内容一致。段头检查器还会从**期望值本身**断言 `p_vaddr == p_offset (mod p_align)`，因此夹具再也不能记录一个违反该关系的布局。

## 诊断说清该改什么

- 未解析引用现在**在它被写下的地方**报出并点名那个操作数，而不是在最后给一个计数。
- 未闭合的虚拟区、改变布局的终结器、`late_layout` 失败、函数内部失败，都会指向**造成它的那一行**；若失败发生在展开内部，还会带上调用点。
- 一行写了两个语句会明说，而不是把第二个报成调用格式错误；include 路径写反斜杠与写正斜杠同样接受。
- **编码器自己的告警不再被丢弃**：位移超出范围会被报出来，而不是被静默编码。
- 那些有位置却只有错误名的错误现在带上了原因；手册里也写清了 `target.isa`、`target.bits` 与布局查询的含义。

## 吞吐

索引化消掉了平方路径：声明大量符号或类型名、以及查一个片段的位置，原先都是"每项一次线性扫描"。

- 16000 条前向引用：408.7 ms → **79.6 ms**，且形状已变为线性。
- 指令片段只编码一次。此前同一片段会被再编一遍，然后再找一个重复项丢掉。
- AArch64 语料（1 万行 + 宏库）由 36.0 s 降到 **10.1 s**。AArch64 指令来自生成的宏库而不是后端编码器，那层解释是剩下的成本：约 **2.0 ms/指令**，随指令数线性增长。

## 更小的命令行

汇编器只负责把源码变成字节；ISA 由源码选择，输出格式由源码 import。命令行现在只说源码说不了的事。

- `--isa` 是正式拼写，`--target` 保留为旧名。它只是给"没有自己选择 ISA 的源码"提供起始目标。
- 接受 `aarch64`、`arm64`、`a64`。AArch64 仍然没有后端编码器（指令来自宏库），但它**可以被正确命名**，不必再"碰巧"用 x86 目标来汇编。
- `xirasm init --template <名字>` 取代 `--isa`/`--bits`/`--os`/`--abi` 的组合，`xirasm help templates` 列出九个模板。AArch64 工程现在**真正脚手架为 AArch64**，不再落到 x86 起步模板。
- 只对 `init` 有效的选项不再列在通用选项里；传给汇编命令时会说明**平台选择究竟在哪里**，而不是回一句"未知选项"。
- 显式 `--target x64` 不再被 `xirasm.toml` 覆盖：选项记录的是"用户到底有没有指定"，而不是拿值去和默认值比较。

## 列表文件与打印的值

- `--listing` 每行**以地址开头**，文件偏移单独成列，并给行分类（`code`、`data`、`resv`、`algn`、`gap`、`trim`）。文件里存在但不属于任何片段的字节以 `gap` 行**显示其真实内容**（而不是留空），被裁掉的尾部预留空间标记为 `trim` 且没有文件偏移——因为文件里确实没有那个字节。
- 由宏或函数展开产生的行会带上**展开深度**并以**调用点**开头，生成的宏体长行会被截断，所以宏库的列表是可读的。
- `print`、`warn`、`err` 与失败的 `assert` 会**缩进展开 list/map 的内容**，不再是 `list#3`/`map#3`。

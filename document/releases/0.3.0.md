# XIRASM 0.3.0

This release is the audit release: the whole frontend was swept for input-derived
unsafety, the layout facts were checked against an independent reader of each
format, and the command line was cut back to the one thing an assembler has to be
told. Three defects that could produce wrong output silently are fixed, and the
diagnostics that were technically correct but unhelpful now say what to change.

## Bounded input, located failures

Nesting had no limit anywhere, so a source file of a few kilobytes could end the
process with a stack overflow and no message at all: 8,000 nested blocks, 16,000
nested parentheses, 4,000 nested `list.of` elements and a 200 KB configuration file
of nested arrays all killed the assembler silently. Every nesting axis is now
bounded and reported with a location and a reason.

- Statements nest 128 levels (`StatementNestingTooDeep`), expressions and aggregate
  literals 64 (`ExpressionNestingTooDeep`, `StructNestingTooDeep`), and documents
  read by `toml.parse`/`json.parse` 64 (`NestingTooDeep`). A flat operator chain is
  not nesting and stays unlimited.
- The TOML scanner proved `pos + 2 <= len` and then read `source[pos + 2]`, so a
  configuration file ending in two quotes (`x = """ab""` with no trailing newline)
  read one byte past the buffer: a panic in a checked build, an unchecked read in a
  release build. Both multiline scanners now require the three bytes they read.
- `\U` escapes accumulated in a 21-bit type, so eight hex digits discarded their
  high bits before the range check and an out-of-range escape wrapped into the
  valid range. Accumulation is wider than the target and the range is checked
  before narrowing.
- `virtual.begin()` with no argument, and the paths that freeze `here()` for a
  stored `defer` or `late_layout`, read the active address without the cursor sync
  every other layout API performs. The cursor only counts an instruction once it is
  encoded, so a segment starting after `mov eax, 1` began at 0x4000 instead of
  0x4005, and a frozen address was wrong the same way. All three sites sync first.

## Layout facts that match their declarations

A shared object placed each segment by keeping its address congruent with the file
offset modulo the page, which is what a loadable segment has to satisfy, but never
aligned the result to the alignment its own sections declare: `.bss` landed at
0x119D and `.data` at 0x219D while declaring an alignment of 8, which is not what
`sh_addr % sh_addralign == 0` promises to code that assumes alignment. The file
position for a segment now starts at that alignment, which moves the address and
the file offset together and keeps the page congruence intact.

Every checked-in format fixture is now read back with an independent reader of the
four formats and checked against four invariants: declared extents stay inside the
file, no two sections overlap in the file or in the address space, declared
alignment is honoured, and header-derived sizes agree with the content. The
program-header checker also asserts `p_vaddr == p_offset (mod p_align)` from the
expectation itself, so a fixture can no longer record a layout that violates it.

## Diagnostics that name the thing to change

- Unresolved references are reported where they were written, with the operand
  named, instead of a count at the end of the run.
- An unclosed virtual region, a finalizer that changes layout, a late-layout
  failure, and a failure inside a function all point at the line that caused them,
  including the call site when the failure happened inside an expansion.
- A line holding two statements says so, rather than reporting the second one as a
  malformed call; an include path written with backslashes is accepted the same way
  a forward-slash path is.
- The encoder's own warnings are surfaced instead of being dropped, so a
  displacement that exceeds its bounds is reported rather than silently encoded.
- The errors that had a location but only an error name now carry a reason, and
  `target.isa`, `target.bits`, and the layout queries answer in the manual.

## Throughput

Indexing removed the quadratic paths: declaring many symbols or type names, and
looking a fragment's placement up, were each linear scans repeated per item.

- 16,000 forward references: 408.7 ms to 79.6 ms, and the shape is now linear.
- Instruction fragments are encoded once. A second pass over the same fragment used
  to re-encode it and then look for a duplicate to discard.
- The AArch64 corpus (10,000 lines, macro library) went from 36.0 s to 10.1 s.
  AArch64 instructions come from the generated macro library rather than a backend
  encoder, and that interpretation is the remaining cost: about 2.0 ms per
  instruction, linear in the number of instructions.

## A smaller command line

The assembler turns a source into bytes; the source picks its ISA and imports the
format layer it wants. The command line now says only what the source cannot.

- `--isa` is the documented spelling, with `--target` kept as the older name. It
  supplies a starting target for a source that does not select one itself.
- `aarch64`, `arm64`, and `a64` are accepted names. AArch64 still has no backend
  encoder - its instructions come from the macro library - but it can be named
  instead of assembled under an x86 target by accident.
- `xirasm init --template <name>` replaces the `--isa`/`--bits`/`--os`/`--abi`
  combination, and `xirasm help templates` lists the nine templates. An AArch64
  project is now scaffolded as AArch64 rather than falling through to the x86
  starter.
- Options that only apply to `init` are no longer listed as general options, and
  passing one to an assembly explains where the platform choice lives instead of
  calling it unknown.
- An explicit `--target x64` no longer loses to `xirasm.toml`: the option records
  whether it was given, instead of comparing the value against the default.

## Listing and printed values

- `--listing` leads each row with the address, keeps the file offset as its own
  column, and types the rows (`code`, `data`, `resv`, `algn`, `gap`, `trim`).
  Bytes the file holds but no fragment claims appear as `gap` rows with their
  contents instead of an empty cell, and reserved space trimmed from the file is
  marked `trim` with no file offset because the file holds no byte there.
- A line produced by a macro or function expansion carries its expansion depth and
  leads with the call site that produced it, and a generated body line is
  truncated, so listing a macro library is readable.
- `print`, `warn`, `err`, and a failed `assert` show a list or map's contents,
  indented, instead of `list#3`/`map#3`.

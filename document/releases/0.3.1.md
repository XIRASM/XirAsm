# XIRASM 0.3.1

This release makes AArch64 sources assemble several times faster, with the
produced bytes unchanged.

## AArch64 lowering is about 3.7× faster

A 100,000-instruction AArch64 source used to spend 377 seconds in parse and
lower. It now takes about 100 seconds, and the output is byte for byte what it
was before.

Two costs dominated. First, every operand a macro captured also captured the
module's value bindings, which meant deep-copying the generated AArch64 tables
once per instruction. Those bindings are now taken once per module generation and
shared by every capture, with a reference count and a generation check that keeps
each capture reading exactly the values it was taken with. Second, a built-in
call whose arguments are all plain names — `map.get(a64_registers, name)` and the
rest of the generated library's lookups — copied the stored map before reading
it; it now borrows the storage it was going to read anyway.

Nothing about the language changes: captures still copy the value bindings
visible where they were taken, and a module-level binding that changes in place
still invalidates them.

## Fixed

- A cached module snapshot could be released while the cache still pointed at
  it, if retaining the caller's reference failed.
- Mutating a module-level collection in place (`map.set_mut`, `list.push_mut`,
  `list.set_mut`) did not invalidate the capture snapshot, so a capture taken
  afterwards could read the value from before the mutation.

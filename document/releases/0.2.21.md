# XIRASM 0.2.21

This release lets the Meta language enumerate directories, and moves Android
resource tables from declaring one resource at a time to scanning a whole
resource tree.

- `fs.list_dir(path)` returns the entry names directly inside a directory as a
  list of strings, sorted in ascending byte order, so a listing never depends on
  the order the filesystem happens to return. `fs.is_dir(path)` reports whether a
  path names a directory and answers false for a path that cannot be resolved,
  while `fs.list_dir` reports an error instead.
- Both use the same controlled resolver as the rest of the file API: the build
  supplies directory support, and a host that cannot enumerate directories
  reports the path as unavailable instead of guessing. Like the other file
  builtins they are unavailable in `late_layout` and `defer`.
- `include/format/apk.inc` scans a resource tree. `apk_res_dir(app, "res")` reads
  it and declares what it finds: a file directory named `<type>[-<qualifier>...]`
  contributes a file resource whose name is the file name before its first dot
  (the archive entry keeps the original name), a `values*` directory contributes
  one string resource per key of its TOML table, and the conventional names
  `app_name` and `mipmap/ic_launcher` bind themselves as the application label
  and icon while the application leaves them unset.
- Scanning is recursive, skips dot entries, and takes its order from the sorted
  listing, so the same tree produces the same bytes every time and scanning it
  twice is harmless.
- Qualifiers are strict, because the table compiles a density axis and a locale
  axis and nothing else. A qualifier is a density name, a two letter locale, or
  an API-version qualifier such as `-v4` that is accepted and not stored. A
  directory may carry one density and one locale; anything else is an error
  rather than a silent omission, and two files claiming one resource in one
  configuration is an error for the same reason.
- String resources now also take a two letter locale configuration, which is
  what a `values-zh` directory becomes.
- The Android guide documents the scanning rules, the acceptance script, and the
  signing boundary: signing stays outside the assembler, and the guide gives one
  complete command sequence built from SDK tools plus what self-signed debug
  certificates need.
- `tests/format/android_gl_demo/` puts the whole stack in one place: a GLES2
  renderer library and the archive around it, both written by the assembler, with
  the texture and the launcher icon generated from a formula at assembly time.
  The result is a 39 KB archive with no DEX, no C++ runtime, and no third-party
  artwork, and the acceptance script rebuilds it from source before `aapt2` and
  `zipalign` read it back.

- A name that fails to resolve now says which name it is. An expression that
  carries an undeclared name is rendered back into the message, an unknown call
  reports the callee, the two errors that used to hide these cases are their own
  again, and the parse-error mapping lists every parser error instead of sending
  the rest to one catch-all. A call statement may also end with a line comment,
  which instruction lines already allowed.

- `deflate.compress` joins the Meta helpers: it returns a raw DEFLATE stream, the
  compressed blocks a ZIP entry of method 8 stores, with an optional level from 1
  to 9. The archive layer gained matching entries, so an APK can hold deflated
  assets next to the uncompressed resource table and shared libraries Android
  requires. The CRC-32 an entry records always covers the uncompressed bytes, and
  an independent decompressor checks it in the acceptance script.

- The Android framework's own resource IDs are available as a generated catalog
  (`format/android/generated/framework_ids.inc`), produced by reading the
  platform jar through aapt2. A manifest can therefore carry
  `@android:style/Theme.DeviceDefault` by ID, which `apk_use_theme_id` writes as
  the application theme.

```asm
import("format/apk.inc")

origin(0)

let app: map = apk_new("com.example.tool", 1, "1.0", "demo")
app = apk_res_dir(app, "res")
apk_emit(app)
```

A resource tree with two icon densities, a locale variant, a drawable, and a raw
file reaches the archive and the resource table together; `aapt2` reads every
resource name, configuration, and archive path back from the result, and
`zipalign -c -P 16 4` accepts it. `zig build test` covers the directory builtins
through an assembled fixture, the chapter 13 reference fixture lists a tree and
asks about a directory and a file, and two negative fixtures pin that a listing
is refused inside `late_layout` and `defer`.

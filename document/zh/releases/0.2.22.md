# XIRASM 0.2.22

这一版把安卓平台面以**生成物**的形式带进汇编器：NDK 的平台符号、头文件声明的常量，以及平台
回传结构体的字节偏移。写原生代码不再需要手打库名、也不再需要自己数字段，而且这两份数据每次
都对着 NDK 复核。

## 安卓平台目录

- `include/os/android/` 收录 **25 个平台库 / 4,137 个符号 / 4,416 条（符号, 库）记录**，覆盖
  API 21–35 与 5 个 ABI，由 NDK 的 stub 库生成。每个符号记录：提供它的库、首次可用 API 级别、
  GNU 版本标签、导出它的 ABI。
- `import("os/android/imports/liblog.inc")` 之后用 `android_import_log___android_log_write`，
  配套的辅助函数把库名焊到导入列表上。x86-64 用 PLT 桩、AArch64 用 GOT 槽位，**由目标决定**，
  源码里不出现 `"liblog.so"`。
- `import("os/android/defs/native_activity.inc")` 是另一半：来自 NDK 头文件的 **1,168 个常量与
  25 个结构体布局（161 个字段偏移）**。渲染器示例装回调用的是
  `android_layout_ANativeActivityCallbacks_onDestroy_offset64` —— 这是**生成的事实**，不是数出来
  的数字。两种安卓数据模型都给出，64 位与 32 位构建各自读对应的一套。
- `import("os/android/catalog.inc")` 按名字回答查询，供工具与诊断使用：符号由哪个库提供、从哪个
  API 起可用、在哪些 ABI 上。数据表**第一次查询时才解析**，不是 import 时。
- 全部可复现：`--check` 逐字节比对生成树与 NDK，manifest 记录 NDK 版本、计数与所用文件的摘要。

## 验证，包括设备上

- `tests/os/validate_android_symbols.py` 用 `llvm-nm` **独立重算**全部事实：缺失、多余、逐库 API、
  逐符号 API、ABI 掩码、版本标签**六项差异全 0**。
- `tests/os/validate_android_constants.py` 把生成的常量与偏移改写成 `_Static_assert`，包含同一批
  NDK 头文件，按 **LP64 与 ILP32** 两种模型编译 —— 值错了是编译器报错，而不是几个月后的程序。
- `tests/os/check_catalog_vs_device.py` 把目录与真实设备导出的符号比对。在本机使用的 Android 15
  镜像上，**3,916 条里有 3,906 条被真实导出（99.74%）**，x86-64 与 AArch64 结果一致；剩下 10 条
  已具名：libz 的 8 个内部符号，以及 libvulkan 与 libEGL 各 1 条。这些是 stub 专有条目，导入其中
  任何一个都会让**整个库装载失败**。
- `tests/os/make_android_smoke.py` 生成"每个平台库抽样导入"的源码：把它装到设备上，装载过程本身
  就验证了几百条"符号→库"映射。两个 ABI 都在执行第一条指令前完成导入绑定，所以**没被调用的导入
  也必须解析成功**。

## 两个 ABI 的渲染器示例

- `tests/format/android_gl_demo/gl-demo-so-aarch64.asm` 是同一个 GLES2 场景的 AArch64 版：平台调用
  走 GOT 槽位加载后跳转，数据标签用 `adrp` 加 `:lo12:` 寻址，`glTexImage2D` 的第九个参数走栈。
- `gl-demo-apk-universal.asm` 把两个库装进一个包：模拟器取 x86-64 那份、真机取 AArch64 那份。
  `tests/format/check_apk.py` 验收两个条目，包括 Android 15 要求的 16 KiB 页对齐。
- 导入段落改走目录之后，x86-64 库仍**逐字节一致**（6,496 字节），AArch64 库 5,968 字节 —— 验收
  脚本会报这两个数字。

## AArch64 与格式层修复

- `:lo12:` 修饰符过去会丢掉标签的拼写（`:lo12:MyData` 去找小写名字）；`ldr xN, label` 有同样的
  缺陷。现在两者都保留源码拼写，`tests/isa/arm/label_case.asm` 一个夹具钉住全部引用形式。
- 生成编码器拒绝操作数时过去只说 "operand value out of range"，现在会**指名操作数与所需倍数** ——
  这正是让"位移没有对齐"可诊断的关键；共新增 136 条诊断。
- 共享对象导入表过去是二次复杂度且递归：约 176 个导入直接汇编失败，97 个导入要 121 秒。现在两张表
  都是单遍前缀和：**188 个导入 6.85 秒**，460 个导入 41 秒。

## 文档与编辑器支持

- `include/os/android/README.md` 与中文版说明两条访问路径、两种导入机制的调用写法、API 级别事实，
  以及**数据到哪儿就不再为真**；`document/os-android.md` 是把它们串起来的章节。
- `tests/os/check_android_docs.py` 把这些页面里的**每个示例都汇编一遍**，文档不会与语言脱节。
- VS Code 扩展随包发布该目录并解析其 include，常量在编辑器内即可补全。
